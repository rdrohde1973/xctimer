## Where the agent was wrong

I first assumed a successful WebFetch meant a claim was confirmed. Many Help Center fetches returned only the page title, which proves the page exists, not what it says. I recorded those as "title only" rather than OK. Also WP-0002's PageView claim (cited to the Pixel reference) is not in the reference table, and the ad-standards intro page does not contain the sensitive-data rule it was cited for.

## Dead ends

Searched for a standalone Meta "non-functional landing page" policy and found none; settled on the match-ad-to-landing-page rule from the Ad Standards intro plus spam rules. Did not find a Meta page stating privacy-policy requirements for lead forms, so left it as unverified house advice.

## Judgment calls

Kept unsupported-but-sensible advice (2FA, mobile-friendly landing page, privacy policy) but labelled it house advice instead of deleting it. Used WebSearch summaries as secondary evidence where fetch returned only titles and said so in the table. Left the "~50 events" claim, since Meta's learning-limited page supports it per the search summary, but QA should confirm in a browser. Removed rows stay in the Source Check table so every original URL has a row.

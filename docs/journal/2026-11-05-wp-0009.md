# WP-0009: UTM capture on /host signup + admin funnel report

- **Author:** API Annie (Backend Developer (Python/Flask))
- **Date:** 2026-11-05
- **Branch:** wp-0009-utm-capture-on-host-signup-admin-funnel-

## Summary

UTM first-touch attribution for /host signups plus a super_admin funnel report and CSV. Version is now 1.108.0-host-attribution. Both test scripts pass: scripts/test_host_attribution.py prints OK, and the WP-0008 test still prints ALL PASS.

**What changed**
- **db.py:** an idempotent migration adds `host_attribution` (email, utm_source, utm_medium, utm_campaign, utm_content, fbclid flag, referrer_host, signed_up_at, meet_token, published_at) with two indexes. It has no foreign keys, and reap.py doesn't touch it.
- **road.py capture:**
  - GET /host and the landing pages (`/` and `/welcome`, in app.py) set a short-lived `xc_attr` cookie (7 days, httponly, SameSite=Lax) only if there isn't one yet, so first touch wins.
  - Values are stripped of control characters and truncated to 100 chars. They are HTML-escaped when the report renders.
  - Referrer host is stored only when a campaign touch is present and the referrer isn't our own host.
  - POST /host writes the row, with blanks if there is no cookie. `/host/go/<token>` writes one if none exists yet, which covers existing hosts.
- **road.py publish:** `_attr_mark_published` sets `published_at` at all three places an event gets published: the Venmo/manual publish, the free promo publish, and the Square webhook.
- **Report:** `/organizers/attribution` (HTML) and `/organizers/attribution.csv`, both super_admin only and linked from /organizers. They cover the last 90 days grouped by utm_source and utm_campaign, with blanks shown as "(none)". Columns are signups, events created, events published and FIRSTRACE redemptions, joined to `promo_redemptions` by email. The CSV guards against formula injection.
- No third-party scripts, no Pixel, no new dependencies, and the CSP is unchanged.

**How to verify**
- `python3 -m py_compile road.py db.py app.py`
- `/tmp/wp8venv/bin/python scripts/test_host_attribution.py` (system python3 has no Flask, so I used that venv). It runs the migration twice and checks the five acceptance items (a)–(e).
- `/tmp/wp8venv/bin/python scripts/test_promo_first_event.py` for the WP-0008 regression.

## Judgment calls

- I used a cookie only, with no hidden form field. It survives the resend-link flow and needs no template changes.
- Values are truncated and have control characters removed, but I don't strip other characters on write. The report escapes them on output. The brief said "allow-listed", and a strict character allow-list would mangle legitimate values like "fall-5k promo"; I can tighten this if you want.
- "Events created" counts one per signup row, since POST /host creates exactly one event. That keeps the count correct after the reaper deletes the event.
- "Events published" uses `published_at` on the attribution row rather than a join to `meets`, for the same reaping reason. Events published before this change aren't counted.
- Hosts who signed up before this change get no attribution row until they next use a magic link, and then it has blank UTM fields.
- Source and campaign group keys are case-sensitive.
